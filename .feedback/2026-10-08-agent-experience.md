# 本次实现反馈记录

## 已遇到的摩擦点

- 项目初始目录为空且尚未初始化 Git，需要先建立规格、计划和基础工程。
- 系统 PATH 没有 Python，但 Codex 工作区依赖提供了 Python 3.12；后续使用固定绝对路径，避免误报“缺少 Python”。
- Impeccable 前端上下文引擎未安装，默认缓存目录不可写且首次安装需要网络，因此无法运行随机概念生成器。本次依据用户已确认的产品流程建立保守的 Operate 界面，并在最终验收中单独检查可用性。
- 当前没有模型权重和 A6000 基准环境；软件接入与准入门槛可以实现，真实性能数据必须留给目标工作站实测，不能伪造。
- 新仓库首次提交因缺少 Git 作者身份失败。处理方式是仅为本仓库设置 `Codex <codex@local.invalid>`，不污染用户全局配置。
- Superpowers 的 `sdd-workspace` 脚本在本机 Git Bash 中找不到 `basename`，脚本没有建立台账。已按脚本公开的目录和首行格式手工建立等价台账。
- pip 的隔离构建在受限网络中两次卡住；改为先在项目 `.venv` 安装 `setuptools`/`wheel`，再使用 `--no-build-isolation` 做可编辑安装。启动脚本已固化这个顺序。

## 改进建议

- 为项目固定一个受控 Python 虚拟环境，并把启动脚本绑定到该解释器。
- 模型安装与平台代码分开验收：先用 Demo 适配器验证状态机，再逐个启用真实 Profile。
- 前端设计工具若要使用，应把引擎缓存配置到可写工作区或预先安装，避免实现中途联网。

## 最终代理体验复盘

- 用户方案同时包含“软件实现”和“硬件/大模型实测”。代码仓库能够交付平台、适配器和准入工具，但无法在没有权重与目标工作站运行证据时诚实宣称 H3/Wan/LTX 已通过。README 和验收清单已把两类完成状态分开。
- Git 沙箱账户与提升权限账户不同，导致仓库出现 dubious ownership；每次提交使用精确的临时 `safe.directory`，没有修改全局配置。更理想的环境应让同一身份创建和提交仓库。
- Impeccable 引擎不可用时，仍通过真实浏览器检查发现并修复了模型页移动端整页横向溢出；说明 DOM 测试不能替代视觉验收。后续可在 CI 加入 390px/1280px 截图回归。
- FastAPI TestClient 当前发出 Starlette 的 httpx 弃用提示，测试仍通过。后续依赖升级时应按 Starlette 建议切换到 httpx2 或其新测试客户端，不应为消除提示而盲目固定旧版本。
- 辅助工具失败均有明确替代路径，但 `sdd-workspace` 对 Windows Git Bash 的 PATH 假设较强，建议脚本自带 `basename`/`dirname` 的 shell 参数展开兜底。
