# 分镜时长与画面比例编辑设计

## 目标

让成员在分镜草稿阶段为每个镜头选择目标时长和画面比例，提交审批后锁定参数。界面不再把所有镜头和入队任务固定为 `5 秒 · 16:9`，并为 MiniMax H3 的 5/10/15 秒档与 LTX-2.3 的 20 秒候选档保留清晰边界。

本次提供的画面选项是 `16:9` 与 `9:16` 的宽高比，不是 720p、1080p 或 4K 分辨率。分辨率仍属于模型运行预设，暂不加入分镜编辑表单。

## 已确认交互

- 草稿镜头显示两个下拉框：时长为 5、10、15、20 秒；画面比例为 16:9、9:16。
- 用户逐镜头保存，保存成功后仍停留在项目页，并看到更新后的值。
- 只有 `draft` 分镜允许编辑；`pending_approval` 与 `approved` 状态只读。
- 待审批分镜提供“退回修改”操作。项目创建者可撤回自己的待审批分镜，管理员可撤回有权访问的待审批分镜。
- 撤回后，项目、分镜和镜头恢复为草稿状态，清除本次提交时间并写入审计日志。
- 提交审批和批准分镜沿用现有流程；批准后参数继续锁定。

## 生成与模型准入

项目页不再把入队参数写死为 5 秒和 16:9，而是使用镜头保存的 `duration_seconds` 与 `aspect_ratio`。

批准后的每个镜头只列出精确匹配当前时长、画面比例且已经通过准入的本地模型 Profile：

- MiniMax H3 只显示 A6000 实测通过的 5/10/15 秒组合。
- LTX-2.3 的 20 秒能力作为候选档；只有本机完成十次基准并满足准入标准后才显示。
- 没有匹配模型时，页面显示“暂无已验证模型”，不允许入队，也不自动缩短时长或改变比例。
- Demo 适配器为验证工作流而开放 5/10/15/20 秒与两种比例的组合，但必须继续明确标记为“不生成真实视频”。这不构成任何真实模型性能证明。

LTX-2.3 官方资料说明模型最长可生成约 20 秒连续音视频，但本设计仍把 A6000 本地实测作为开放 20 秒档的必要条件：

- 官方模型页：https://ltx.io/model/ltx-2-3
- 官方技术报告：https://videos.ltx.io/LTX-2/grants/LTX_2_Technical_Report_compressed.pdf

## 后端与数据流

现有 `Shot.duration_seconds`、`Shot.aspect_ratio` 和 `PATCH /api/shots/{id}` 数据结构保持不变，不需要数据库迁移。

新增服务层的草稿镜头更新函数，由 JSON API 与服务端表单共同调用，统一完成访问权限、草稿状态、时长档位、画面比例和审计校验。服务端页面使用普通 POST 表单，避免为了两个字段引入复杂前端状态管理。

新增待审批撤回服务和 POST 路由。该操作只接受 `pending_approval`，其他状态返回明确错误；已批准分镜不能通过撤回路径改回草稿。

项目页面在服务端计算每个镜头的可用 Profile 列表，沿用现有 `admit_generation` 作为唯一准入判断。API 入队仍进行相同校验，不能依靠前端选项绕过模型准入。

## 错误处理与权限

- 非项目成员不得修改镜头或撤回分镜。
- 普通成员只能撤回自己创建项目的待审批分镜；管理员遵循现有项目访问规则。
- 非法时长、非法比例、非草稿修改和非待审批撤回均返回可读错误，不静默修改数据。
- 重复提交、刷新页面或手工构造请求不能绕过 CSRF、项目权限和状态机校验。

## 测试与验收

自动测试覆盖：

1. 草稿页显示 5/10/15/20 秒和 16:9/9:16 控件。
2. 保存后数据库与页面值一致，并产生审计记录。
3. 待审批或已批准镜头不能修改。
4. 待审批分镜可以由合法用户撤回，非法用户和非法状态被拒绝。
5. 批准后的页面只显示精确匹配镜头参数的已验证 Profile。
6. 入队任务使用镜头保存的时长与比例，不再使用硬编码值。
7. Demo 的八个组合可完成流程测试，且输出仍明确为演示清单而非视频。

人工验收使用一个包含 5、10、15、20 秒及横竖屏镜头的项目，逐项验证草稿编辑、撤回、审批、模型筛选、入队和队列展示。真实 H3/LTX 档位是否开放仍以 A6000 基准记录为准。

## 不在本次范围

- 720p、1080p、4K 分辨率选择。
- 安装或下载 LTX-2.3、MiniMax H3 权重。
- 改变真实模型的十次基准准入标准。
- 已批准分镜的直接编辑；需要修改时应新建分镜版本，后续单独设计。
