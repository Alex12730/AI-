# AI 视频工作站软件补全设计

## 背景与范围

现有 MVP 已具备账号权限、项目与分镜审批、镜头参数、持久化队列、单 GPU 串行执行、模型准入、基础媒体质检和归档追溯。对照用户提供的三个豆包对话，缺口集中在运行监控、可视化编辑、产物预览和本地后期流程，而不是重新建设队列或权限系统。

本设计采用已确认的“方案 A”：先补齐不依赖 RTX A6000 的软件功能，并在页面上如实区分“平台支持”“本机已配置”“A6000 已验证”三种状态。当前开发机只有 GeForce GT 730 2GB，不能据此声称 Wan 2.2、MiniMax H3 或 LTX-2.3 已经能够生产运行。

整体工作拆成三个按顺序交付的子阶段，每个阶段都能独立测试和验收：

1. 运行监控与告警。
2. 分镜编辑与产物预览。
3. 本地 FFmpeg 后期任务。

真实模型权重安装、A6000 基准、CosyVoice/MuseTalk 实际口型效果、Video2X 性能和 72 小时稳定性测试不在本轮软件补全范围内，必须到目标工作站执行。

## 设计原则

- 保留现有 FastAPI、Jinja2、SQLite WAL、单 Worker 架构，不引入前端框架或额外消息队列。
- 监控失败不能拖垮 Web；生成失败不能影响其他项目页面。
- 页面只展示可证明的状态，不把“存在 Profile”显示成“模型可用”。
- 所有文件访问继续经过登录、项目权限和系统生成路径校验，不能把任意磁盘路径暴露成下载接口。
- 后期任务与视频生成共用现有持久化队列，继续保证同一时刻只有一个重型任务。
- 不接入 Seedance、Midjourney、Context-IR、Regenerate-2K 或其他云端生成服务。

## 子阶段一：运行监控与告警

### 目标

管理员可以在“运行状态”页面快速判断工作站、Worker、磁盘和模型是否具备接收任务的条件；普通成员只能看到与创作相关的简化状态，不能修改系统配置。

### 组件

新增独立的系统探测服务，负责以固定参数数组调用 `nvidia-smi`，读取 GPU 名称、利用率、显存已用/总量、温度和驱动信息；使用 Python 标准库读取数据目录、临时目录和归档目录的磁盘空间。命令不经过 Shell，设置短超时并限制输出长度。

Worker 启动、空闲和运行时都更新持久化心跳。为此增加一个小型 `WorkerStatus` 数据实体，保存 Worker 标识、状态、当前任务、最后心跳和启动时间。它只描述进程可见性，不替代现有任务租约和 `Task.heartbeat_at`。

模型状态拆成三层：

- 已登记：数据库存在 Profile。
- 已配置：本地命令数组、版本和量化信息完整，并通过离线配置校验。
- 已准入：当前时长与画幅有通过 A6000 基准的记录。

页面不能仅凭 `enabled=True` 显示“可生产”。Demo Profile 始终标记为演示，不算真实视频能力。

### 告警规则

首版告警为站内只读告警，不发送邮件、微信或第三方消息。告警从实时探测和数据库状态计算，不新增复杂的告警状态机：

- GPU 温度达到 80℃：严重。
- 显存使用率达到 92%，或可用显存少于 4GB：严重。该规则在 A6000 上约等于 44GB 已用，同时也能适配其他显卡。
- 任一受管磁盘剩余不足 100GB，或不能满足下一任务的两倍预计临时空间：严重。
- Worker 最后心跳超过两个心跳周期：离线。
- 队列存在任务但没有健康 Worker：严重。
- 连续出现两次 OOM 或同一模型连续基础设施失败：警告，建议管理员选择已经验证的低显存档，不自动降级参数。

所有探测都返回 `ok`、`warning`、`critical` 或 `unavailable`。`nvidia-smi` 不存在、超时或输出无法解析时显示“无法获取”，Web 仍返回正常页面。

### 接口与页面

- `GET /api/system/status`：管理员使用的结构化状态接口。
- `GET /system`：运行状态页面，显示 GPU、磁盘、Worker、队列和模型准备度。
- 全局导航显示一个简短状态点；只有严重告警时使用醒目提示。
- `/health` 继续只作为轻量存活检查，不执行慢速 GPU 探测。

## 子阶段二：分镜编辑与产物预览

### 分镜编辑

草稿分镜的单镜头表单扩展为可编辑以下字段：

- 镜头标题。
- 正向提示词。
- 负面提示词。
- 镜头类型：`product_ui`、`broll`、`character`、`series_drama`。
- 时长和画幅。

`product_ui` 继续强制走真实录屏或截图动效，不允许选择 AI 视频模型。保存仍调用统一服务层校验并写审计日志；待审批和已批准分镜保持只读。批量时长与画幅功能不改变，也不批量覆盖提示词。

### 资产登记

非 Demo 生成任务通过媒体质检后，除更新任务结果外，还要创建 `Asset(kind="video")`，保存项目、镜头、任务、系统生成路径、SHA-256 和质检元数据。重复处理同一任务不得重复创建资产，因此 `(task_id, kind)` 需要形成幂等约束或等价的服务层保证。

Demo 任务不制造假视频资产，只继续保存演示结果，并在页面显示“演示任务未生成媒体”。

### 安全预览与下载

新增受保护的资产读取路由。服务端先验证登录和项目访问权，再确认数据库记录指向允许的输出目录或归档目录内的规范化文件。路径越界、符号链接逃逸、记录不存在或文件丢失都拒绝请求。

视频响应支持浏览器播放所需的 Range 请求，使用正确的媒体类型和 `Content-Disposition`。页面不接受用户提交任意文件路径，也不直接暴露磁盘绝对路径。

项目页在任务列表下增加“生成资产”区域：

- 每个镜头显示最新成功视频的内嵌播放器、模型、版本、量化、随机种子、时长、画幅和质检结果。
- 历史资产折叠显示，避免多个视频自动加载。
- 提供同权限下载按钮。
- 文件丢失或质检失败时显示明确状态，不出现空白播放器。

### 质检展示

首版读取现有 ffprobe 结果，展示视频轨、音轨、时长、编码和分辨率。黑帧与异常静帧检测仍保留为“待目标素材校准”，不在当前开发机上伪造阈值。

## 子阶段三：本地 FFmpeg 后期任务

### 任务模型

沿用现有 `Task.task_type`，增加受控类型：

- `compose_project`：按镜头顺序合并已经选定的项目视频资产。
- `encode_delivery`：输出 H.264/AAC、1080p、16:9 或 9:16 的交付文件。
- `upscale`：调用管理员已经配置并准入的本地 Video2X Profile；默认关闭。

这些任务仍进入同一持久化队列。Worker 根据受控 `task_type` 选择内部执行器，不允许客户端提交任意命令。FFmpeg 命令由程序根据数据库资产和固定模板构造参数数组，提示词或文件名不进入 Shell。

### 合成规则

- 输入只允许选择本项目中已经通过质检的视频资产。
- 默认按镜头序号排列；缺少镜头资产时拒绝合成并列出缺失项。
- 不静默拉伸画面；画幅不一致时按已选交付画幅进行等比缩放并补边。
- 音轨缺失时可以生成静音轨，确保最终文件结构统一；这不代表完成配音。
- 字幕采用管理员上传并确认的 UTF-8 SRT 文件，登记为本项目的 `Asset(kind="subtitle")`。首版限制单文件不超过 2MB，只接受可解析的时间轴和纯文本内容；文件复制到系统管理的项目资产目录后才能烧录，不引用外部 URL 或任意磁盘路径。系统不自动生成虚构台词。
- Logo、片头片尾和转场使用固定本地模板；模板不存在时拒绝该选项，不影响基础拼接。
- 合成结果再次执行媒体质检并登记为 `Asset(kind="composite")`。

### Video2X 边界

页面可以显示“超分（默认关闭）”开关，但只有 Video2X Profile 已配置且对应档位通过目标工作站测试时才允许入队。当前开发机上该开关必须为禁用状态并说明原因，不能回退到云端服务。

### 本轮不实现的生成能力

Qwen 自动拆解、CosyVoice 3 配音、MuseTalk 1.5 精确口型和本地语音识别对齐保留为后续独立阶段。当前设计为它们预留资产类型和队列任务边界，但不新增虚假的“已完成”按钮。

## 数据流

1. 用户编辑草稿镜头并提交审批。
2. 管理员批准后，系统只展示已经配置且对应档位准入的模型。
3. 镜头任务进入单 Worker 队列；Worker 心跳同步到运行状态页。
4. 真实模型输出通过媒体质检后登记视频资产。
5. 有权限的用户在项目页预览、下载和选择资产。
6. 全部必需镜头具备合格资产后，管理员创建合成任务。
7. FFmpeg 本地合成、编码并再次质检；合格成片登记为 composite 资产。
8. 管理员完成最终人工验收后，沿用现有归档流程写入追溯清单。

## 错误处理与恢复

- 系统探测错误只影响该项监控状态，不影响页面和队列。
- 资产数据库记录存在但文件缺失时标记为 `missing`，不自动删除记录，保留审计依据。
- Range 参数非法返回 416；无项目权限返回 403；记录不存在返回 404。
- 合成前做完整输入检查，任何输入缺失都不启动 FFmpeg。
- FFmpeg、Video2X 和模型命令超时或非零退出沿用基础设施失败策略，最多自动重试一次。
- 媒体质检失败归类为质量失败，只能人工返工。
- 服务重启后，后期任务和生成任务使用同一租约恢复规则，不重复输出或覆盖已登记资产。

## 权限与安全

- 普通成员可编辑自己有权限项目的草稿镜头、预览和下载该项目资产。
- 只有管理员可以查看完整系统状态、创建交付合成任务、启用 Video2X 和最终验收归档。
- 所有写请求保留 CSRF 校验；资产读取保留登录和项目授权校验。
- 日志和告警不得包含密码、Cookie、完整提示词或任意本地敏感路径。
- 不添加用户自定义 Shell 命令、任意输出目录或外部 URL。

## 测试与验收

### 自动测试

- `nvidia-smi` 正常、缺失、超时和畸形输出都能转换为稳定状态。
- GPU、磁盘、Worker 和队列告警规则边界正确。
- Worker 空闲时仍更新心跳；陈旧心跳显示离线但不破坏任务租约。
- 模型的已登记、已配置、已准入三层状态不会混淆。
- 草稿镜头可编辑新增字段；无权限、非法类型和非草稿修改均被拒绝且不部分保存。
- 成功任务只登记一个视频资产，Demo 不登记假视频。
- 资产播放、Range、下载、权限和路径越界测试全部覆盖。
- 字幕上传拒绝非 SRT、超限、非法时间轴和路径逃逸文件；合法字幕只对所属项目可见。
- 合成任务拒绝缺失/未质检输入，使用固定参数数组并生成可追溯资产。
- Video2X 未配置或未准入时不能入队。
- 全量现有测试保持通过。

### 人工验收

- 在没有 NVIDIA 工具的环境仍能打开运行状态页，并明确显示不可用原因。
- 在当前 GT 730 上显示真实型号和资源数据，不误称 A6000 已验证。
- 新建草稿项目，修改提示词、负面提示词、镜头类型、时长和画幅，刷新后保持一致。
- 使用本地短样片模拟已完成资产，验证页面播放、拖动、下载和无权限隔离。
- 用两个本地样片完成 FFmpeg 拼接与 1080p H.264/AAC 编码，并通过结构质检。
- 模型页面明确区分 Demo、已配置未准入、已准入三种状态。

## 完成标准与诚实边界

本轮完成后，可以声称“工作站管理软件具备监控、编辑、预览和本地后期任务能力”。仍不能声称“Wan/H3/LTX 已在 A6000 上跑通”或“可以稳定生产 30–60 秒成片”，直到目标工作站完成真实权重安装、各档十次准入、30–60 秒样片、归档盘和 72 小时混合任务验收。

## 实施顺序

1. 先实现运行探测、Worker 状态和系统页面，因为它能为后续模型接入提供可见证据。
2. 再实现完整镜头编辑、资产登记和安全预览，让生成结果真正可操作。
3. 最后实现 FFmpeg 合成与交付编码，再增加受准入限制的 Video2X 任务入口。
4. 每个子阶段分别执行目标测试、全量回归、编译检查和浏览器验收；全部通过后再统一上传 GitHub。
