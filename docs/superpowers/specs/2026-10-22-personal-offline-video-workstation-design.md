# 个人全离线视频工作台设计补充

日期：2026-10-22。状态：供用户审阅的设计稿，尚未实施。代码依据：本地提交 `460697d`；本次已重新读取业务代码、启动脚本和模型数据库。

本文件补充既有工作站设计。与旧文档冲突时，本次用户确认后的个人使用流程、Windows 本机部署和零公网依赖要求优先。没有冲突的队列、权限、模型准入、媒体质检和追溯设计继续保留。

## 1. 用户目标与完成标准

用户是视频模型新手，需要兼顾产品教程、知识讲解、口播、故事短片和创意广告。日常制作不使用 Codex，不操作 ComfyUI 节点，不写命令，不手填模型参数，不购买云端生成服务。

目标体验：双击桌面“视频工作台” → 说明想做的视频、放入素材 → 确认分镜 → 自动安排模型、生成和合成 → 看成片并保存。单人使用只保留两个人工检查点：开始制作前确认内容，完成后决定是否导出或重做某个镜头。

成功必须同时满足：

- 关闭 Codex、拔网线/关闭 Wi-Fi 后，重启电脑，仍能从桌面入口完成一条视频。
- 应用代码、Python、ComfyUI、模型、字体、模板和帮助都在本地；不引用 Codex 缓存目录和开发工具的 Python。
- 生成期间没有公网 DNS、HTTP、HTTPS、遥测、检查更新、素材搜索或缺文件自动下载。不得失败后转云端。
- 只在“已安装、输入能力匹配、当前配置通过本机生产验收”的模型中自动选择。
- 一次提交自动完成后续依赖任务，关闭界面后任务继续，重开能看到进度；重启后保留已完成镜头。
- 所有自动推荐可解释；用户可以只改一个镜头，无须重做整片。

约定：“不使用流量”在本项目中指不使用互联网流量。`127.0.0.1` 是电脑内部通信，允许保留。要让整台电脑的其他软件也不产生任何公网流量，最可靠的使用方式是物理断网；本工作台不能替其他应用作零流量承诺。

## 3. 采用的方案

| 方案 | 优点 | 代价与结论 |
| --- | --- | --- |
| A. 保留本地网页，补专用运行环境、桌面启动器和制作向导 | 最大限度复用已有代码，日常无命令；断网可用 | 推荐作为第一阶段交付 |
| B. 再封装独立窗口和固定版本 WebView 运行时 | 更像独立软件，便于限定宿主外联 | 作为后续封装，不能先花时间重写视频业务 |
| C. 直接以 ComfyUI 节点界面为日常入口 | 可调参数多 | 学习成本高，不符合用户目标；仅供维护使用 |

不新建另一套视频生产平台，不同时引入云服务、远程账户、插件市场和复杂时间线编辑器。保留现有 FastAPI、SQLite、Jinja2、Worker、FFmpeg 和 ComfyUI。

## 4. 首页与四步制作流程

默认导航只有“开始制作”“我的作品”“素材库”；“帮助与设置”放到底部。运行监控、模型参数、账号管理和维护入口放入设置。首页主按钮只有“开始制作”，下方提供“继续上次制作”。

保持现有暖白底、深色文字、清楚的状态和系统中文字体。调整的是操作结构，不用重新学习一套花哨的界面。

### 第一步：告诉工作台想做什么

主问题为“你想做一个什么视频？”，带三个可直接填写的示例。类型可自动判断，也可点选：产品与教程、知识与口播、故事与创意。

默认只显示：

1. 需求描述或现成文案。
2. 时长：30 秒、60 秒、自己填写；这是整片目标，不是要求模型一次生成这么长。
3. 画面方向：横屏“电脑/课程”，竖屏“手机短视频”。

点击“加入素材”可拖入视频、图片、音频和本地字幕。“声音”默认选择“保留素材声音/暂不加配音”；系统根据已安装能力提供“我自己录”“导入声音”“本地配音”。未准备好的选项说明原因，不让用户开始后才遇到失败。

### 第二步：确认系统安排的镜头

分镜以顺序列表显示：画面要做什么、说什么、来自哪里、预计占几秒。用户通常只改文案或替换素材。

例：“第 2 段：展示真实软件操作；用你导入的录屏，不需要生成。”或“第 4 段：生成办公室氛围画面；自动选择 Wan，原因：这一段不需要同步对白。”

高级信息折叠后才显示模型名、种子、负面提示词和已验收参数。人物是否需要逐字念稿、产品是否必须保持原样，是醒目的内容约束，不作为技术参数隐藏。

主按钮“确认并开始制作”。个人模式将旧有“提交审批→批准分镜”合并为这个动作；服务端仍以当前用户身份记录批准、版本快照和审计，不删除权限校验。团队模式保留原来的审批流程。

### 第三步：自动制作

显示“正在制作第 2/6 段”“正在配音”“正在合成”，而非只显示一个总百分比。镜头按项目顺序呈现，完成的可以先看。无可靠估计时显示阶段，不编造剩余分钟数。

默认开始后自动跑到可预览成片。可选“每段生成后让我先看”，该选项默认关闭。

“暂停后续制作”表示当前镜头完成后暂停；不承诺暂停任意扩散采样步骤并无损续算。“停止当前生成”使用任务 ID 定向取消，说明当前镜头需从头重做；已经完成的镜头保留。

### 第四步：预览和保存

成片播放器为主，按钮为“保存视频”“只改这一段”“复制项目”。保存旁提供“打开文件夹”；高级下载再提供分镜素材、字幕和制作记录。

返工只有三个常用动作：“换一版画面”“修改描述”“换成我的素材”。生成新版本后由用户选择替换，不自动覆盖满意版本。

默认导出横屏 1920×1080 或竖屏 1080×1920、24fps、H.264/AAC。导出尺寸不代表模型原生生成了 1080p，也不代表提高了真实细节。超分作为另行验收的高级选项，默认关闭。

## 5. 必须内置的六条制作流程

| 流程 | 用户提供 | 系统安排 | 缺少条件时 |
| --- | --- | --- | --- |
| 产品介绍/软件教程 | 卖点、真实截图/录屏、可选配音 | 真实演示为主体，标题和字幕由本地合成，少量生成氛围镜头 | 真实界面缺失则要求补素材或改成纯文字介绍，不生成假界面 |
| 知识讲解 | 讲稿、可选录音/图片 | 分段解释，搭配素材/图文/空镜，字幕与音频对齐 | 无本地配音时提供录音或导入，不启用云配音 |
| 真人口播剪辑 | 用户自己拍的口播 | 整理片段、加字幕和插画面 | 第一阶段不承诺自动去所有口误；保留原片和确认点 |
| AI 人物表演/氛围短片 | 场景、人物动作与声音偏好 | H3/LTX 候选生成短段，用户确认声音和画面 | 不保证指定台词逐字正确 |
| 故事短片 | 故事、角色说明、可选参考图 | 按场景拆短镜头，冻结人物设定，再组合成片 | 参考图流程未接通时明确限制；不保证仅靠同一种子保持同一张脸 |
| 创意广告 | 产品真实素材、卖点、文案 | 真实产品特写与生成环境镜头组合，末尾加清晰字幕/行动文案 | 商标、价格、包装文字使用真实图层，不交给视频模型绘字 |

附加“从已有视频开始”：即使生成模型临时不可用，用户仍可在本地导入、整理、加字幕并合成。模板包含分镜结构、素材检查、声音策略和导出默认值，不能只有几段提示词。

## 6. 自动选模型的明确规则

以下是针对当前已接入版本的初始路由政策，不是三模型画质排名。最终偏好需要用本机、同题材、同交付条件的对比样片校准。

| 画面或约束 | 默认处理 | 自动匹配理由 |
| --- | --- | --- |
| 软件按钮、操作步骤、准确文字、产品外观 | 用户真实视频/图片 + FFmpeg 图层 | 需要准确和可验证，不应生成替代事实 |
| 风景、环境、运动、转场空镜，不需要原生声音 | Wan 2.2 优先 | 当前已接通画面生成，声音另行处理 |
| 需要环境声或人物表演的短镜头 | MiniMax H3 优先，LTX 为候选 | 当前 H3/LTX 接入均能输出音视频，按匹配档位和对比反馈选择 |
| 希望比较另一种音视频表达，或已验收的较长单镜头 | LTX-2.3 候选 | 只有本机相应时长已验收才可用，不能因为“支持 20 秒”就默认选它 |
| 必须逐字说出一段话，但不要求人物对口型 | 录音/导入音频，或已安装的离线配音 + 画面 | 把台词准确度与画面生成解耦 |
| 必须出现说话人物且口型对齐 | 真人录制，或已验收的独立口型流程 | 当前三模型原生音频不作为精确口型保证 |
| 跨镜头同一角色 | 已验收参考图流程 + 角色素材约束 + 人工连续性检查 | 不把“同一种子”当作身份锁定技术 |

决策顺序固定为：用户硬约束 → 素材优先 → 功能门禁 → 当前配置准入 → 题材偏好 → 本机历史耗时与失败记录。LTX、H3 不因原生有声音就被判断为“任何视频都比 Wan 好”。

系统返回推荐方案、理由和可用备选。没有候选时应提出“改成两个已验收短镜头”“换真实素材”等具体办法，得到用户确认再变更；不能自动降画质、换台词、换方向或转云端。

自动选模型的单位是镜头。60 秒广告可以混用真实素材、Wan、H3 和 LTX，不要求整片只选一个模型。默认生成单位先收敛到已验收的 5 秒镜头，再逐步开放 10/15/20 秒。

## 7. 声音、字幕、文案的边界

三种视频模型不能覆盖完整视频生产链。

- 已有视频编码器不直接充当聊天/写稿服务。第一阶段采用可编辑内置脚本模板和确定性分镜规则；自由描述的本地编导作为独立能力包，接入现有 `qwen-local` 配置，另行固定模型、运行时与权重版本并验收。缺包时必须明确处于模板模式。
- 精确讲稿优先支持用户自己的录音和导入音频，避免基础流程额外依赖大模型。后续接通现有 `cosyvoice-3` 配置后才显示“本地配音”；每句合成、试听后以实际音频时长规划镜头。
- 自动字幕需要独立本地转写/对齐能力包。未安装时提供导入 SRT 或逐句文案+人工校时，不把按字数估算的时间轴标成“准确识别”。
- `musetalk-1.5` 作为可选精确口型包；先完成图像、人脸、音频、对齐和输出验收，再启用数字人口播模板。
- 原生环境音与讲解音轨分开管理。出现精确旁白时可降低或移除原声，但若画面中有明显说话口型，不能宣称换音轨后口型仍同步。
- 背景音乐只能来自用户本地文件或打包且允许使用的素材。默认不加音乐，不提供在线搜歌入口。

能力包都是“首次部署时准备或从 U 盘导入”，日常制作绝不触发下载。用户不需要管理其模型名，设置页用“帮我写稿”“自动配音”“识别字幕”“人物对口型”表达用途。

## 8. 首次准备与生产验收

设置向导统一显示三种状态：“文件已准备”“试片已成功”“正式制作已验证”。不得用一个绿色“已安装”掩盖后两项。

首次向导依次完成：选择数据盘、检查专用运行环境、核对模型文件、准备基础素材/字体、生成小样、运行所选正式档位、试听检查、断网验收。耗时任务可以退出界面后继续，结果保存在本地，不在每次新建视频时重复测试。

第一批正式档位建议为三个模型 × 5 秒 × 横/竖两个方向；每组合沿用十次规则，共 60 次，不承诺很快完成。可先验收实际急需的一个组合，其余后台分批进行。需要用户确认一次测试范围后才开始，不因打开首页自动占满 GPU。

继续遵守每档 10 次、至少 9 次成功、无 OOM、无损坏文件。成功样本保留实际耗时、显存、内存、温度和音画检查记录。自动采样客观指标，声音/画面一致性仍需要真实人工评价；不得为满足数据库字段伪填同步分数或画质分数。

对比画质时提供同一题材样片并由用户选择偏好；这种偏好只用于适配已通过技术验收的模型。样片通过不代表任意提示词都成功。

配置指纹扩展到模型文件校验值、工作流、桥接器、引擎版本和关键依赖。版本改变后原档位显示“需要重新验证”。不能仅更改模型文件却沿用旧十次记录。

## 9. 全离线与独立启动

### 部署闭包

代码目录、运行目录、模型目录、用户项目目录分开；路径来自部署清单，允许安装在当前 E 盘并通过启动器定位。现有权重复用，不重复复制百 GB 文件。

```text
安装目录/
  app/                         工作台代码、模板和本地帮助
  runtime/workstation-python/   专用业务 Python，不依赖 Codex
  runtime/ComfyUI/              已锁定的生成引擎与专用 Python
  runtime/ffmpeg/               视频处理工具
  models/                      共享的本地权重
  resources/                   字体、模板、示例、离线帮助
  deployment.json              位置、版本、校验值和能力清单
用户数据目录/
  projects/ assets/ archive/ logs/ workstation.db
```

离线包需包含全部 Python 依赖、节点依赖、音频处理器、分词器、模型配置和字体。将当前宽范围依赖单独锁定为经过验收的安装版本；源码开发依赖不等于离线安装包。

缺少文件时明确说“缺少本地配音文件，请在设置中导入离线包”，立即停止该功能，不能自动访问 Hugging Face、ModelScope、GitHub 或 pip。所有路径应可在设置中“检查/重新定位”。

### 运行期约束

- 业务 Web 只监听 `127.0.0.1:8000`，ComfyUI 只监听 `127.0.0.1:8188`；本次默认关闭局域网使用。
- 模型加载使用本地路径和支持的离线选项；启动前核验资源闭包。相关库可设置 `HF_HUB_OFFLINE`、`TRANSFORMERS_OFFLINE` 等，但环境变量不能替代实际断网测试和系统约束。
- 禁止在线字体、CDN 脚本、统计上报、自动检查更新、自动安装节点；只允许打包好的已审核节点。
- 应用自己的 URL 策略只放行回环，禁代理和重定向，前端 CSP 限制资源为本地同源。
- 对专用运行进程配置可逆的公网出站限制，保留本机回环；实际规则必须验证。当前业务 Python 的基础进程属于 Codex 缓存，迁移前不能直接给这个共享 Python 加全局阻断规则。
- 普通浏览器自身可能存在独立后台联网行为，不能算作工作台已控制的进程。整机零流量使用断网；若要求电脑同时联网办公而该窗口也严格不外联，后续使用专用受限窗口宿主，不能阻断用户日常浏览器。
- 离线模式里隐藏 GitHub 登录、更新和上传入口。维护更新使用完整离线包，验证后手动切换版本，可回退。

### 桌面入口

提供真正可双击的 Windows 快捷方式，后台启动器执行环境检查、单实例判断、启动本机服务、等待就绪、打开本地操作页。用户不用右键运行 PowerShell，不看到终端。

任务进程独立于 Codex和网页窗口。关闭窗口时提醒“任务继续/完成当前段后暂停”，不默认杀掉 GPU 任务。关机前持久化状态；下次只重做未完成的当前镜头，不承诺恢复采样器中间显存状态。

统一现有两个启动路径使用的会话密钥位置，避免手动启动与计划任务互相使登录失效。默认不自动登记开机任务；首次设置可选“登录 Windows 后自动准备”，包含引擎、Web、Worker 的一致启动顺序。

## 10. 整片编排和错误恢复

在现有单 GPU Worker 上增加“制作计划”，不是另起第二套并行队列。

制作计划依次包含：素材校验 → 分镜冻结 → 音频准备 → 按镜头渲染/导入 → 媒体检查 → 当前版本选择 → 字幕时间轴 → 合成 → 成片质检 → 本地导出。

每节点记录输入版本、执行参数、所依赖资产、结果和失败原因。只有依赖成功才入队，重复点击“继续”不得重复出片。合成只引用计划快照中的明确资产 ID，不能简单挑目录中最新文件。

重做镜头时标记依赖它的合成为过期，已完成的其他镜头继续复用。自动完成技术步骤后默认选择通过质检的新结果；用户手动选定的版本不能被后台新任务覆盖。

所有使用 GPU 的视频、未来文案、配音、识别和口型任务都遵守统一资源调度。必要时卸载上一个模型以留出余量，不同时启动三个大模型抢显存。检测到维护人员直接在 ComfyUI 中运行其他任务时等待或说明引擎占用，不抢占或中断别人任务。

错误用普通中文说明：

| 原因 | 用户看到 | 操作 |
| --- | --- | --- |
| 未验收 | 这个制作规格还没验证 | 打开准备向导，或确认改用已验证短镜头 |
| 缺真实素材 | 这一段需要真实操作画面 | 加入录屏或改成图文说明 |
| 显存不足 | 当前设置超出显卡能力 | 保留已完成结果，确认拆短或选已验证方案 |
| 磁盘不足 | 保存空间不足 | 显示所在磁盘和清理预览，不自动删原素材 |
| 模型文件缺失 | 所需文件不在本机 | 重新定位目录或导入离线包 |
| 指定台词不适配 | 这个人物镜头不能保证逐字说稿 | 选真人录制、画外音或已准备的口型流程 |

基础设施错误保留现有有限重试；OOM、画质问题和用户取消不无限重试。运行中取消必须从项目→队列→Worker→本次 ComfyUI prompt_id 全链路生效，不能只改界面文字。

## 12. 交付顺序

### 第一阶段：独立离线、三类题材均可完成的基础制作

交付专用运行环境和桌面启动；模板化需求输入、真实素材优先、自动路由、整片串行生成、录音/导入声音、字幕导入/编辑、自动合成和预览导出。保留模板模式的边界，不把它宣传成已经有自由写稿模型。

先让“录屏教程”“配自己声音的知识视频”“由短生成镜头构成的创意片”分别跑通。三类入口都存在；未准备的精确口型等选项明确不可用，而不是暗中调用替代服务。

### 第二阶段：减少准备工作

接通本地文案、配音、字幕转写/对齐能力包，导入和设置都通过工作台完成；加口型包前先验证它与用户素材的适配。经批准可增加固定运行时的独立窗口。

### 第三阶段：角色与画面控制

接通参考图片和首尾帧、角色素材卡、跨镜头检查，再扩展较长档位和可选超分。长片仍通过分镜拼接，不能用单个视频模型“任意连续生成”替代。

不在设计阶段承诺各阶段天数或每分钟出片速度。根据第一轮本机正式档位记录再估计，尤其不能用加载缓存后的小样耗时推算整片耗时。

## 13. 必须通过的验收场景

1. 全部资源准备完成后断网、关闭 Codex、重启，从桌面打开并完成新项目；同时观察应用进程的外联记录，不能仅凭页面上的“离线”标识通过。
2. 检查所有运行进程路径，不引用 `.codex`、开发技能目录或系统临时安装器。
3. 需求“教程中的按钮名称必须准确”时只路由到真实素材/本地文字图层。
4. 同一项目包含录屏、空镜、音视频表演时分别匹配，已验收约束逐镜头生效。
5. 三模型只有 configured、没有准入记录时，不产生生产任务；Demo 不计为真实生成成功。
6. 请求不存在的 20 秒 H3 时，提出拆镜或其他已验收方案，用户确认前不改需求。
7. 请求逐字讲稿时，不以 H3/LTX 的自由原生对白冒充精确配音。
8. 中文目录、含空格文件名、中文提示词，以及以 `--` 开头的文字都能正确处理。
9. 制作到中途关闭网页，重开能看到进度；重启电脑后复用已完成且通过校验的镜头。
10. 运行中停止只影响本项目自己的任务；任务未真正终止时不能显示“已停止”。
11. 第三个镜头返工只使它与后续合成失效，前两个镜头和原满意版本保留。
12. 缺字幕/配音包时清楚提示并保留录音、导入或人工校时路径，全程无下载请求。
13. 合成检查编码、音轨、时长、黑帧/异常静帧；画质、事实准确和音画观感仍由人预览，自动质检不能替代内容验收。
14. 用户不接触模型页、不打开 Codex、不操作命令，能按内置帮助完成三类示例作品。

## 14. 用户需要审阅的决定

确认本稿时主要确认：采用统一四步向导；个人模式合并自我审批；第一阶段先用录音/导入和模板做全离线闭环；高级能力按本地包准备度逐项启用；正式模型仍先完成一次性本机档位验收。

确认设计稿后再写逐任务实施计划，并选择执行方式。本稿尚不表示这些新按钮与流程已经出现在现有网页中。
