# 企业微信温度提醒接入设计

## 目的

把本机 GPU 温度状态实时推送到指定企业微信群。模型、提示词、素材和视频仍在本机处理；企业微信只接收最小化的运行告警信息。

## 选定方案

使用独立通知进程。现有温度监控进程继续每 5 秒采样、判断阈值并原子写入状态；通知进程读取状态变化，负责企业微信发送、去重、持久化待发消息和失败重试。通知网络故障不得阻塞温度采样、任务队列或高温保护。

不采用“温度监控直接发送”，因为 HTTP 超时会干扰采样；不采用 n8n 等中间服务，因为当前只有一个告警渠道，不需要额外运维层。

## 本机配置

- 新增“配置企业微信温度提醒”Windows 入口。
- 用户只在主机本地粘贴完整 Webhook 地址；不得在网页源代码、Git、日志或命令行参数中保存。
- 配置入口验证地址必须为 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...`。
- Webhook 使用 Windows DPAPI 按当前 Windows 用户加密，密文保存在工作站数据目录；启动器解密后只通过子进程环境传递给通知进程。
- 配置完成后立即发送一条不含作品内容的测试消息；测试成功才启用。
- 提供更换、停用和删除配置的入口。

## 推送规则

| 状态变化 | 推送行为 |
| --- | --- |
| 80℃持续 30 秒进入 warning | 推送一次黄色预警 |
| 85℃持续 30 秒进入 cooldown | 推送一次红色告警，说明新任务已暂停 |
| 90℃持续 10 秒或单次 93℃进入 emergency | 立即推送紧急告警；未恢复时每 10 分钟最多重复一次 |
| 低于 75℃持续 2 分钟进入 recovery_ready | 推送一次恢复通知，提示需要在工作台确认继续 |
| 温度监测失联进入 unavailable | 推送一次监测失联告警；恢复后推送一次恢复消息 |

相同状态的每 5 秒采样不重复推送。所有推送远低于企业微信每个消息推送每分钟 20 条的限制。

## 消息内容

允许发送：工作站名称、告警等级、GPU 温度、显存占用、GPU 利用率、采样时间、系统已经采取的保护动作和本机工作台提示。

默认禁止发送：Webhook、账号密码、完整文件路径、文案、提示词、图片、音频、视频和模型权重信息。

## 可靠性和安全

- 请求只允许 HTTPS 官方主机和固定 Webhook 路径，不使用系统代理，不跟随重定向，连接和读取均设置短超时。
- 企业微信返回非零 `errcode` 视为失败；响应正文和完整 URL 不写日志。
- 未发送事件保存在本地通知状态文件，采用退避重试；新紧急告警优先于普通恢复通知。
- 通知进程崩溃或网络中断时，高温状态判断和队列门禁继续工作。
- Webhook 不加入 Git，密文文件也位于仓库外的数据目录。

## 用户操作

1. 在企业微信内部群创建“消息推送”，复制 Webhook 地址。
2. 双击主机上的“配置企业微信温度提醒”。
3. 在本机弹窗中粘贴完整地址，确认保存。
4. 企业微信群收到“连接测试成功”消息。
5. 日常启动工作台时，通知进程自动启动；无需再次粘贴。

## 验收条件

- 正确 Webhook 可以保存并收到测试消息；错误域名、HTTP 地址、缺少 key 的地址被拒绝。
- Webhook 不出现在 Git、进程命令行、页面、标准输出和服务日志中。
- warning、cooldown、emergency、recovery_ready、unavailable 的状态转换各按规则推送。
- 连续相同温度样本不刷屏；紧急重复提醒间隔不少于 10 分钟。
- 模拟断网时温度仍每 5 秒更新，重型任务门禁仍生效；联网恢复后待发告警补发。
- 未配置或停用机器人时，工作台和温度保护继续正常运行。

## 后续边界

本次先接企业微信温度提醒，不同时实现邮箱、手机短信、85℃定向中断当前 ComfyUI 镜头或局域网访问；这些作为独立任务继续实施。
