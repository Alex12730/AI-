# 一句话到成片：全本地创作链补充设计

日期：2026-10-22。状态：用户已回复“好的继续”，补充设计已确认，进入分阶段实施计划。本文承接已确认的个人全离线工作台设计 1.1 与第一批简易制作代码，不表示以下新增能力已经部署或通过验收。

## 1. 已确定的用户目标

用户不想在其他软件生成文案、绘制角色、准备配音或剪辑。工作台应接受一句话，内部完成文案、角色形象、分镜、声音、视频与合成，所有结果允许修改，日常完全离线、无需 Codex。

2026-10-22 用户明确选择：**每步先预览确认，再继续下一步**。这是默认行为，不能在确认文案后未经许可自动消耗算力制作所有后续内容。

入口继续保留三大用途：产品与教程、知识与口播、故事与创意。角色设计在需要人物的作品中启用；不强制所有教程、空镜和真实录屏都创建角色。

## 3. 页面流程：一份作品，逐步确认

顶部显示一个作品流程条：“想法 → 文案 → 角色 → 分镜 → 声音 → 镜头视频 → 成片”。用户无需理解模型名称，模型参数放进高级设置。用不到的步骤明确显示“本作品无需此步骤”。

每一步只有主要结果、修改入口和一个主按钮。模型生成时有阶段状态；后台持续工作，用户可以关闭页面。任务未完成时不能显示下一步已就绪。

### 想法与文案

用户填一句话，例如“做一个小女孩在森林寻找萤火虫的温暖故事，约一分钟”。工作台生成标题、概要、完整文案、拟用角色与建议时长，明确这是草稿。

文案编辑区可随时保存；提供“更简短”“更口语”“改结尾”“按我的要求修改”和“另写一版”。这些动作调用本地写作模型，不只是替换预设句子。新结果单独展示，由用户选择替换；不能覆盖用户已手动修改的版本。

文案确认后只进入角色/分镜准备，不自动开始视频推理。长文与时长不匹配时给出具体调整建议，由用户选择缩短文案或增加时长。

### 角色形象

为每个角色建立角色卡：姓名、年龄段、外观、服装、声音偏好及禁止改变的特征。支持本地生成候选形象和导入自己的形象图，选择一版后锁定角色 ID 与图像版本。

更换角色图必须显示受影响的镜头。仅将描述复制进提示词、复用种子或显示角色缩略图，都不能当作已经实现角色一致性。未接通并通过验收的参考图视频流程不得显示“一键保持同一角色”。

### 分镜与预览图

镜头列表每项包含：镜头序号、画面描述、旁白/台词、出场角色、景别/运动、预计时长和素材来源。用户可以改写、添加、删除或调整顺序；可只重新生成选定镜头的文案或预览图。

需要生成画面的镜头可先生成静态预览图供确认。真实软件界面、包装文字、商标和价格仍使用真实素材或本地确定性文字图层。不会为凑齐流程而生成假的软件操作。

### 声音

提供“本地生成配音”“导入已有录音”“保留原声/无旁白”。音频导入目标格式为 WAV、MP3、M4A，具体解码能力以捆绑 FFmpeg 实测为准。当前旧页面尚无此入口，接通后再开放按钮。

配音按旁白段落生成，可以试听、更换已部署声音、修改文字后只重做该句。记录实际音频时长后安排镜头，不能按字符数伪造精准时间轴。

整段录音支持作为整片旁白使用；逐字字幕需要独立的本地识别/对齐流程。缺少该能力时允许导入 SRT 或手工校时，不把模型猜测的时间标为准确识别。

默认旁白优先：有旁白时明确选择移除原生人声、压低环境声或保留原声。人物精确说台词并对口型属于独立门禁；原生音视频生成不保证逐字台词与口型。

### 镜头视频

自动选择已部署、输入能力匹配、当前档位已验证的流程。界面显示选择理由，用户可在可用候选间切换。角色图/分镜图必须进入实际执行请求并纳入指纹。

先生成并播放镜头候选；“满意，使用这版”“重做这一段”“修改描述”保留历史。当前新功能不得沿用“只能在草稿阶段编辑”的限制，确认后修改通过创建修订版完成。

### 剪辑与成片

先提供简单的镜头列表剪辑：调顺序、选版本、设入点/出点、替换画面、配音与字幕开关、音量、淡入淡出。第一版不承诺完整专业剪辑软件的多轨编辑器。

自动合成后提供视频预览、字幕检查、保存视频及导出素材包。旁白不得因视频模型时长网格而被截断；必要时建议补镜头、调整画面长度或延长作品，由用户确认。按实际时间轴验收整片时长。

## 4. 版本与依赖合同

每次确认产生版本，最少保存 `project_revision`、`script_revision`、`character_revision`、`storyboard_revision`、`voice_revision`、`timeline_revision` 以及明确的 asset/task ID。

| 修改 | 需要重新检查/生成 | 可继续保留 |
| --- | --- | --- |
| 文案标点或注释 | 相关字幕/文本显示；若朗读改变则重配音 | 不受影响的画面 |
| 一句旁白 | 对应句子的声音、对齐和受影响的时间轴 | 角色图与无关镜头 |
| 一个镜头描述 | 该镜头预览图、视频、成片 | 其他镜头和没有改变的旁白 |
| 角色形象 | 引用该角色的镜头及最终成片 | 不含此角色的镜头和声音 |
| 镜头顺序 | 时间轴、字幕时间及成片 | 已生成的镜头素材 |
| 只改音量 | 混音和成片 | 文案、角色图、镜头视频 |

输出通过哈希、模型/工作流/依赖版本、输入资产版本与质检记录判定是否可复用，不采用“只要项目里有一个视频就算完成”的判断。确认操作保持幂等，过期编辑不得覆盖新的已确认版本；并发修改返回明确冲突和恢复选项。

所有阶段提供保存和历史；“随时能修改”表示可建立新修订版，不代表后台执行中的输入会被直接改写。用户确认过的结果继续保存，回退版本可恢复到原状态。

## 5. 本地运行与模型部署约束

继续复用当前队列和单 GPU 串行调度，不为文字、绘图或声音另建相互竞争的执行器。写作/绘图/视频阶段按需加载，释放上一阶段显存后再运行后续任务。

新增模型必须先核实官方来源、许可证、硬件适配、所需空间与依赖闭包；本设计不预先编造具体模型的速度、中文能力或一致性结果。现有 Kokoro/Wav2Lip 优先核验能否复用，未通过时再选择替代方案。

区分首次部署和日常运行。首次部署需要下载必要文件，也可以从离线介质导入；准备完成后的日常创作不得请求公网、自动补下载或失败转云端。项目专用 Python、写作服务、绘图、配音、视频、字体和帮助须全部脱离 Codex 缓存。

缺少能力时显示“本机尚未准备好”和具体准备步骤；不显示会在点击后才失败的伪可用功能。

## 6. 实施顺序和每阶段验收

1. **本地文案与修订基础**：真正的一句话生成、改写、保存和版本选择；界面合并类型选择与对应说明，避免重复入口。验证生成稿可编辑、手改不丢、重新打开可继续。
2. **声音闭环**：独立录音导入/试听和配音服务核验接入；按实际时长安排，验证中文音频、长短句、重配某句与导出混音。
3. **角色与分镜图**：绘图能力部署、角色卡、候选版本与分镜图；验证角色引用随快照传递，未具备参考能力的流程明确阻塞。
4. **参考图到视频**：分别接通支持的 Wan/LTX/H3 输入组合并正式验收；只有通过的组合才开放自动路由，不要求三模型都支持所有模式。
5. **列表剪辑与整片合成**：版本选择、时序、音轨、字幕、准确时长与导出；跑完整作品并检查修改影响范围。
6. **独立启动与断网交付**：专用运行环境和桌面入口贯穿部署，最终在退出 Codex、重启电脑、断网条件下从一句话完成视频。

各阶段先完成真实接口和结果，再显示对应的操作按钮。不再把“模型配置中有一行”或“工作流名称已显示”当作部署完成。

最终验收必须在同一工作台完成：一句话生成文案 → 手改一句 → 生成并锁定角色 → 改一个分镜 → 本地配音及导入录音 → 逐镜头确认视频 → 调整顺序 → 合成保存 → 修改旁白后仅重做相关声音/后期。全程无外部创作软件、云端模型或 Codex 操作依赖。
